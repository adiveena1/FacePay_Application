=== Page 3 ===
The Problem
UPI authentication still relies only on a PIN or OTP — both knowledge-based  
factors that can be phished, SIM-swapped, or socially engineered.
Higher-value transactions carry the largest losses
Facial verification in existing research is optional, not enforced
No system binds liveness-verified identity to the payment itself
UPI fraud · Lok Sabha data
₹981 Cr
in FY25, across 12.64 lakh incidents — up  
from ₹573 Cr in FY23
FacePay · 03/13 — Source: Lok Sabha reply, Union Minister of State for Finance (IANS, Dec 2025)
=== Page 4 ===
Objectives
Flutter-based mobile payment app with QR-based  transaction initiation Mandatory facial liveness verification for transactions  above ₹500
Blink + head-pose liveness checks to reject printed-photo and  replay spoofing 100% on-device biometric processing — no face data ever leaves  the phone
Simulated end-to-end payment lifecycle via the  Razorpay sandbox Gamified streaks & badges that reinforce secure payment habits
Bilingual Hindi-English interface suited to campus-scale deployment

Literature Survey
Source Year Approach Key Finding
IJFMR 2025 CNN / ViT-based UPI face authentication ~96% accuracy; proves on-device feasibility

JETIR 2025 Face recognition + proxy-detection ML ~85% fraud reduction reported

The gap: verification is consistently optional, not enforced — FacePay makes it mandatory above ₹500.

How It Works
Scan → Threshold Check → Liveness → Decision → Payment → Reward
01
Scan & Amount Check
QR scanned; face check triggers only above ₹500
02
Face Detection
Camera confirms a single live face is present
03
Liveness Verification
Blink + head-pose checks block spoof attempts
04
Decision Logic
Pass continues; fail allows limited retries
05
Payment Execution
Razorpay sandbox processes the transaction
06
Reward Update
Streak incremented, badge unlocked, logged

5. Problem Statement
India's UPI ecosystem continues to process a very large share of the country's retail digital payments, and fraud has grown alongside it. Data presented by the Union Minister of State for Finance in the Lok Sabha shows UPI-related fraud rising from Rs. 573 crore in FY23 to Rs. 981 crore in FY25, spanning 12.64 lakh reported incidents in FY25 alone. Current authentication methods such as PIN and OTP are vulnerable to phishing, SIM-swap, social engineering, and stolen credentials, especially for higher-value payments. This project addresses the need for mandatory facial verification for UPI transactions above Rs. 500, using liveness detection and secure on-device mobile processing to reduce fraud and improve trust in digital payments.

7. Project Description
The proposed project focuses on developing a mobile payment security app that enforces facial verification before completing higher-value UPI transactions. The app is designed for college students, small merchants, and educational institutions, where fraud prevention, payment trust, and ease of use are important.
Scope of Work
QR-based payment flow
Facial verification (liveness check) before payment approval
Liveness detection using blink and pose verification
Payment simulation through Razorpay sandbox
Local gamification such as streaks and badges
Hindi / English user interface
Privacy-first on-device processing
Out of Scope
Live NPCI connectivity
Production UPI deployment
Backend server infrastructure
Cross-border payments
Non-UPI payment systems
Identity-matching face recognition against a stored user profile — the current prototype verifies that a live, single face is present (liveness only); embedding-based identity matching is listed under Future Scope (Section 11) and is not part of this build
Structure of the Project
Input Layer: QR scan, payment amount, user identity request
Processing Layer: Face detection, liveness verification, amount threshold check, transaction validation
Application Layer: Payment status, badge system, logs, and UI screens
Modules (Brief)
QR Scan Module: Scans merchant QR for payment initiation
Amount Verification Module: Checks whether facial authentication is mandatory
Face Authentication Module: Captures live face and verifies liveness
Payment Module: Executes sandbox payment flow
Gamification Module: Awards streaks and badges
Transaction Log Module: Stores activity locally
Settings / Language Module: Handles Hindi-English UI and privacy preferences
Customer Usage Flow
1. User opens the FacePay app
2. Scan merchant QR code
3. Enter / confirm payment amount
4. Is amount > Rs. 500?  →  No: proceed with normal UPI payment processing
Yes: face scan required
5. Liveness detection (blink + head-pose check)
6. Liveness passed  →  fraud check  →  Razorpay sandbox payment  →  success
Liveness failed  →  limited retry, then transaction cancelled
This flow is consistent with the FacePay synopsis, which defines a Flutter app with QR-based UPI transactions requiring mandatory liveness-verified face authentication above Rs. 500. The identity-matching step shown in earlier drafts of the flow has been removed here to keep the description consistent with the current prototype's scope (liveness only); it remains a planned future enhancement.
8. Project Modules: Design/Algorithm
1. Input Data
Obtain transaction amount
Obtain merchant QR / UPI request
Access live user camera feed
Define threshold amount T = Rs. 500
2. Preprocessing
Validate QR/payment data
Initialize camera and face frame capture
Prepare face landmarks for liveness detection
3. Transaction Threshold Check
If payment amount > T, facial authentication becomes mandatory
Else normal sandbox payment can proceed
4. Face Detection
Detect human face in real time
Ensure a single face is visible in frame
5. Liveness Verification
Check blink detection
Check pose or movement verification
Reject static photo spoof attempts
6. Decision Logic
If liveness success = true, allow payment continuation
Else retry up to a limited number of attempts, then cancel transaction
7. Payment Execution
Trigger Razorpay sandbox payment flow
Record transaction status locally
8. Reward / Secure Habit Logic
Update streak count
Unlock badge / secure payment milestone
Save achievement in local storage
9. Output
Payment success / failure message
Updated streak / badge
Local transaction record
Fraud-safe verification result

10. Result & Conclusion
FacePay Secure proposes a practical solution for improving UPI payment security by making facial liveness verification mandatory for higher-value transactions instead of keeping it optional. The key strength of the project is its combination of on-device liveness verification, payment simulation, and gamified secure-habit formation in a single mobile app. Overall, the system is privacy-focused, student-relevant, scalable for campus use, and suitable as a strong PBL prototype.
11. Future Scope and further enhancement of the Project
The project can later be improved by integrating:
Live UPI / NPCI-compliant production flow
Stronger anti-spoofing techniques
Face embedding-based identity matching, to confirm the payer's identity and not just liveness
Institution payment systems such as canteen, hostel, and fee payments
Multi-factor biometric support like face + fingerprint
Cloud analytics dashboard for fraud monitoring
The current version is only a sandbox-based pilot and is aimed at a campus-scale deployment rather than a production rollout.
12. Advantages of this Project
Improved Payment Security – adds stronger identity-adjacent verification for high-value transactions.
Fraud Reduction – targets fraud caused by phishing, stolen credentials, and OTP misuse.
Privacy-Focused – uses on-device face processing rather than cloud dependency.
Student-Friendly Use Case – suitable for campus canteens, hostel payments, and institutional collections.
Behavioural Gamification – encourages secure habits using streaks and badges.
Scalable Prototype – can be expanded from campus pilot to broader fintech use.
13. Outcome
The FacePay Secure project demonstrates a working concept for reducing fraud in UPI-based payments through mandatory liveness-verified facial checks for transactions above Rs. 500. The prototype combines Flutter-based mobile development, liveness detection, QR-based transaction flow, and gamification features into a single secure payment application. This outcome shows the project's academic relevance, practical value for campus payment systems, and potential for future enhancement into a larger fintech security solution.
